Business Problem & Objective
During peak flight disruption events, airline operations teams experienced a 35–45% spike in average case handling time and a 20–30% rise in passenger escalation volume. Rebooking, compensation, and seat reallocation workflows were fragmented — no automated handoffs between systems, no documented escalation criteria, and no real-time SLA visibility for team leads.
Project Objective

Analyse the end-to-end flight booking and disruption rebooking process, identify workflow inefficiencies and requirement gaps, and propose a structured to-be process improvement with measurable business outcomes.

Scope

In Scope

  • Disruption detection → case closure workflow
  • Rebooking, reprotection, and compensation process
  • SLA monitoring and escalation criteria

Out of Scope

  • GDS system configuration or infrastructure changes
  • Revenue management and fare pricing decisions

Root Cause Analysis 5-Whys Method
Problem: SLA breach during peak disruption events
W1

Agents cannot process cases fast enough

→ Agents spend 3–5 min manually searching GDS per case

W2

GDS search is fully manual

→ No API integration between disruption module and GDS availability data

W3

No API integration exists

→ Original system built for normal operations — disruption workflows excluded from original scope

W4

Disruption workflows excluded from original scope

→ Sponsor prioritised booking and check-in flows; disruption handling deferred as "Phase 2" — never delivered

RC

Root Cause: Incomplete original requirements scope

Fix requires a targeted requirements exercise for disruption-specific flows AND a phased GDS API integration project.

User Stories 10 core stories with acceptance criteria
US-01 · Operations Agent
As an operations agent, I want to see all affected PNRs in one screen so that I can prioritise cases by SLA urgency.
AC: Screen loads within 3 seconds; sorted by SLA remaining time; colour-coded by breach risk level.
US-02 · Operations Agent
As an operations agent, I want pre-populated rebooking options so that I can offer alternatives without manually searching GDS.
AC: Minimum 3 options displayed; filtered by availability and booking class match; loads within 3 seconds.
US-03 · Passenger
As a passenger, I want to receive disruption notification within 30 minutes so that I can plan alternative arrangements.
AC: Automated SMS and email sent within 30 minutes of confirmed disruption status with flight details and options link.
US-04 · Team Lead
As a team lead, I want an SLA breach alert so that I can intervene before a case breaches its deadline.
AC: Alert fires at 80% SLA consumption; shows agent name, case ID, and time remaining.
US-05 · Operations Manager
As an operations manager, I want a disruption KPI dashboard so that I can monitor team performance in real time.
AC: Dashboard shows OTP%, AHT, SLA compliance%, CSAT, and case volume — refreshes every 5 minutes.
US-06 · Operations Agent
As an agent, I want auto-calculated compensation eligibility so that I don't need to manually reference EU261 regulations.
AC: System displays Yes/No + amount + regulation basis; agent can override with documented reason.
US-07 · Compliance Officer
As a compliance officer, I want complete case audit logs so that I can retrieve full action history for any case.
AC: All 12 required fields logged per action; retrievable by case ID or date range within 30 seconds.
US-08 · Operations Agent
As an agent, I want clear escalation criteria so that I know exactly when to escalate a case to a supervisor.
AC: Escalation triggers documented for 6 defined case types; accessible within the case management system.
US-09 · Passenger
As a passenger, I want a confirmed rebooking itinerary within 2 hours of disruption notification.
AC: System records booking confirmation timestamp; SLA tracked from disruption declaration time.
US-10 · Operations Manager
As an operations manager, I want post-disruption reports generated automatically so that I can submit to the client within 24 hours.
AC: Report covers volume, SLA%, CSAT, compensation paid, escalations, and root cause summary.
